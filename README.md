# 🏥 بوت مركز الشفاء الطبي – صنعاء، اليمن

بوت محادثة يعمل من سطر الأوامر (CLI) بلغة Python، يجيب زوار «مركز الشفاء الطبي» بالعربية اعتماداً **حصرياً** على ملف الأسئلة الشائعة `faq.json`، ويفهم اللهجات العربية (اليمنية والخليجية والفصحى)، ولا يخترع أي معلومة.

> ⚠️ **تنبيه:** بيانات `faq.json` (الأسعار، العنوان، رقم الهاتف…) **توضيحية** لأغراض العرض، وتُستبدل ببيانات المركز الفعلية قبل أي استخدام حقيقي.

## 1. الفكرة الهندسية

| التحدي | الحل المعتمد |
|---|---|
| **منع الهلوسة (Zero Hallucination)** | يُضمَّن محتوى `faq.json` كاملاً داخل الـ System Prompt (Context Stuffing بدل RAG؛ كافٍ لقاعدة معرفة صغيرة). يُمنع النموذج صراحةً من استخدام أي معرفة خارجها، مع `temperature=0.1`. |
| **اختلاف اللهجات** | لكل سؤال في الملف حقل `dialect_hints` فيه صياغات يمنية وخليجية شائعة («بكم الكشفية؟»، «متى تفتحوا؟»، «فين موقعكم؟»). النموذج مطالب بربط المعنى لا الألفاظ، وتحمّل الأخطاء الإملائية، ثم الرد دائماً بعربية واضحة ومهذبة. |
| **رد «لا أعرف» مخصص** | يستخرج النموذج موضوع سؤال الزائر ويصوغ اعتذاراً يذكره، ثم يحيل إلى رقم المركز الموحد، مع تعليمات بتنويع الصياغة وعدم تكرار جملة جامدة. |
| **السلامة الطبية** | يُمنع التشخيص ووصف الأدوية والجرعات؛ تُعامل كأسئلة خارج الملف. الحالات الطارئة تُوجَّه للطوارئ. |
| **مقاومة التلاعب** | قاعدة تتجاهل أي طلب لتغيير التعليمات أو كشفها. |
| **الاعتمادية** | إعادة محاولة تلقائية (مع انتظار متزايد) عند الازدحام أو انقطاع الشبكة، ثم رد احتياطي ثابت فيه رقم المركز، دون أي معلومة مخترعة. |

## 2. التقنيات والملفات

- Python 3.10+
- **النسخة الأساسية `bot_groq.py`:** [Groq API](https://console.groq.com) بالنموذج `openai/gpt-oss-120b` (مجاني، سريع، بدون بطاقة)، عبر مكتبة `requests` مباشرة.
- **نسخة بديلة `bot.py`:** Gemini API عبر `google-genai` (النموذج يُضبط من `GEMINI_MODEL` لأن Google تغيّر أسماء النماذج المتاحة دورياً).
- `python-dotenv` لقراءة المفاتيح من ملف `.env`.

```
shifa-bot/
├── bot_groq.py       # النسخة الأساسية (Groq)
├── bot.py            # نسخة بديلة (Gemini)
├── faq.json          # قاعدة المعرفة (20 سؤالاً)
├── requirements.txt
├── results.pdf       # جدول نتائج الاختبار
├── .gitignore
├── .env              # (محلي فقط، لا يُرفع إلى GitHub)
└── README.md
```

## 3. التثبيت والتشغيل

```bash
# 1) استنساخ المشروع
git clone <رابط-المستودع>
cd shifa-bot

# 2) (اختياري) بيئة افتراضية
python -m venv venv
venv\Scripts\activate          # ويندوز
# source venv/bin/activate     # لينكس/ماك

# 3) تثبيت المتطلبات
pip install -r requirements.txt
```

**4) إعداد المفتاح:** أنشئ ملفاً باسم `.env` بجانب `bot_groq.py` وضع فيه:

```
GROQ_API_KEY=ضع_مفتاحك_هنا
```

المفتاح المجاني من: https://console.groq.com/keys . ويمكن اختيار نموذج آخر بإضافة `GROQ_MODEL=اسم_النموذج`.

**5) التشغيل:**

```bash
python bot_groq.py
```

للخروج اكتب `خروج` أو `exit`.

**النسخة البديلة (Gemini):** ضع في `.env` السطرين `GEMINI_API_KEY=...` و`GEMINI_MODEL=gemini-3.8-flash` (أو أي نموذج متاح لحسابك في AI Studio)، ثم `python bot.py`.

> 🔒 لا ترفع ملف `.env` إلى GitHub أبداً؛ `.gitignore` يمنع ذلك.

## 5. حساب التكلفة التقريبية لكل 1000 سؤال

**المعادلة:**

```
التكلفة = (Tokens_الإدخال × سعر_الإدخال + Tokens_الإخراج × سعر_الإخراج) × 1000 ÷ 1,000,000
Tokens_الإدخال = System Prompt (القواعد) + حجم FAQ + السؤال
```

**تقدير المتوسطات** (العربية تستهلك Tokens أكثر من الإنجليزية؛ القيم تقريبية وتُقاس فعلياً من حقل `usage` في رد الـ API):

| العنصر | Tokens تقريباً |
|---|---|
| قواعد الـ System Prompt | ~900 |
| محتوى `faq.json` (20 سؤالاً) | ~3,000 – 3,500 |
| سؤال الزائر | ~30 |
| **إجمالي الإدخال** | **~4,000 – 4,500** |
| الرد | ~100 |

**مثال بتسعيرة Gemini 2.5 Flash المدفوعة** (≈ 0.30$ لكل مليون إدخال، و≈ 2.50$ لكل مليون إخراج؛ تقريبية، تحقق من صفحة التسعير الرسمية):

```
الإدخال : 4,400 × 1000 = 4.4 مليون × 0.30$ = 1.32$
الإخراج :   100 × 1000 = 0.1 مليون × 2.50$ = 0.25$
الإجمالي ≈ 1.6$ لكل 1000 سؤال (≈ 0.0016$ للسؤال)
```

**التشغيل المجاني:** الباقة المجانية في Groq (وكذلك Gemini) تتيح الاستخدام بتكلفة 0$ ضمن حدود الطلبات والـ Tokens (لـ `gpt-oss-120b` حسب المنشور وقت الكتابة: نحو 30 طلباً/دقيقة و8 آلاف Token/دقيقة؛ راجع حدود حسابك في لوحة Groq). وبما أن كل سؤال يرسل ملف الأسئلة كاملاً، فالسعة المجانية تناسب التجربة والاستخدام المحدود، أما الحجم الكبير فيحتاج باقة مدفوعة أو تحويل المشروع إلى RAG لتقليل حجم الإدخال.

> بيانات الباقات المجانية قد تُستخدم لتحسين منتجات بعض المزودين، فلا ترسل بيانات مرضى حساسة.

## 6. تطويرات مستقبلية مقترحة

- ذاكرة محادثة قصيرة لأسئلة المتابعة («وكم سعرها؟»).
- RAG عند تجاوز قاعدة المعرفة عشرات الصفحات لتقليل التكلفة.
- سجل (Log) للأسئلة غير المجاب عنها لتحديث `faq.json` بانتظام.
